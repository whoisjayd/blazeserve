# Governance

BlazeServe is a small, maintainer-led open-source project. This document describes the current decision-making model; it does not imply a committee or a formal foundation.

## Maintainer responsibility

The current maintainer has final responsibility for releases, security, compatibility, and project direction. The maintainer may ask contributors and users for review, testing, and technical input before making a decision.

Decisions should be discussed publicly in [Issues](https://github.com/whoisjayd/blazeserve/issues) or [Discussions](https://github.com/whoisjayd/blazeserve/discussions) whenever practical. Proposals should include technical evidence, compatibility considerations, and CI or focused-test results where relevant. Security vulnerabilities follow the private process in [SECURITY.md](SECURITY.md), not public discussion.

## Contribution and review

Contributions are evaluated on:

- correctness and user-visible behavior;
- security and safe data handling;
- portability across supported Python versions and operating systems;
- maintainability and fit with the documented project purpose;
- tests, documentation, and operational impact.

The maintainer may request changes, defer a proposal, or close work that is out of scope, unsafe, insufficiently supported, or inconsistent with the project's compatibility commitments. The [Code of Conduct](CODE_OF_CONDUCT.md) applies to all project spaces.

## Becoming a maintainer

A sustained contributor may propose taking on maintainer responsibility by opening a public discussion with the current maintainer. Maintainer access is granted by the repository owner after demonstrated, trusted participation and agreement on the responsibilities involved. Contributions alone do not create access or decision-making authority.

Maintainers are expected to protect project security, review changes carefully, preserve supported-platform behavior, and keep project policies current. Changes to the governance model should be documented publicly.
